# Project notes

This POC compares personal, organizational, and event memory in a LangGraph workflow. Read `README.md` for startup commands, `docs/design.md` for scope and source rules, and `docs/testing.md` for the evaluation protocol.

The default `duckdb` backend is a deterministic retrieval test double. The Compose `live` profile runs Hindsight with Ollama. App source snapshots and retry state live in DuckDB; chat checkpoints use SQLite. `ANSWER_MODEL=extractive` keeps the baseline source passages visible, while `ANSWER_MODEL=llm` tests generated answers over opened passages.

Run `docker compose run --rm --entrypoint python app -m pytest -q` after code changes. For evaluation, ingest fixtures before `docker compose run --rm app evaluate`. Generated answers require manual numeric claim review; the recorded grounding metric checks opened source integrity.
Run `docker compose run --rm --entrypoint python app scripts/render_report.py` after evaluation to refresh the self-contained `results/report.html`.
The optional Compose `reports` service serves these generated files read-only at `http://localhost:8765/`.
The eight-case `data/eval_challenge.jsonl` dataset is separate from the nine-case baseline and should be evaluated with `--cases` and a distinct output directory.
`docs/benchmarks.md` compares published datasets for scoped retrieval, shared organization knowledge, and multi-principal access. None of those datasets has a native disaster-event bank; keep their labels and scores separate. The local challenge set is diagnostic, not an external benchmark.
`scripts/run_memory_bench.py` replays a small paired sample of the external memory-bench dataset with witness ACLs; the data must be downloaded separately. Its HTML report is diagnostic and must not be described as an official benchmark score because the local model/judge protocol differs. See `docs/benchmarks.md` for the exact command and dataset revision.
When `results/memory-bench/review.json` contains verdicts for the same run ID, the report shows a visual pair summary and expandable evidence. These verdicts are assistant qualitative checks of the displayed published criteria. Re-render the HTML after changing the review file; do not rerun ingestion solely to refresh the page.
The benchmark runner passes the published task as `retrieval_query` to the graph. The full framed prompt remains the answer question. Runs generated before this change used the full framed prompt for retrieval, so their saved results must not be described as measuring the new query path.
Use the extractive benchmark run to assess whether Hindsight and the graph opened the target source; use `ollama_native` only as a separate generated-answer experiment. The tiny `qwen2.5:1.5b` model invented a quarterly schedule even when given only the exact event sentence saying runbook review occurs solely after major incidents. A `review.json` with `metric: "source_coverage"` makes the visual report label opened target events as retrieval coverage rather than semantic answer success.
The local default model is now `qwen2.5:7b`. A comparison using the same previously retained Hindsight banks found 4/8 assistant-reviewed answers met the displayed criterion with 7B, versus 2/8 with 1.5B. Those banks were originally populated using 1.5B, so the comparison isolates answer generation, not Hindsight extraction. See `results/memory-bench-7b/report.html`; these counts are not official memory-bench scores.
The live Compose default now uses `RETRIEVAL_MODE=hybrid`: Hindsight recall plus authorized, synchronized source-line ranking from the DuckDB source registry. `MemoryService` defaults to Hindsight-only unless the caller opts in; CLI and benchmark runner pass the configured mode. Hybrid supplements successful recalls and does not conceal Hindsight errors. The benchmark runner now applies each probe's simulated event timestamp as both effective and knowledge cutoff, including when reusing saved ledgers. Label hybrid and Hindsight-only results separately.
With the same saved banks and strict per-probe source-time filtering, the hybrid retrieval diagnostic opened all 8/8 published target events, compared with 6/8 in the earlier Hindsight-only replay. The hybrid 7B answer diagnostic met 5/8 visible criteria by assistant review; retrieval success is not answer correctness. A fresh sequential ingest with 7B was started but stopped because CPU extraction was too slow for this bounded POC run, so the hybrid reports remain saved-bank diagnostics rather than clean fresh-bank benchmark results.
The public repository includes the static HTML/JSON reports under `results/` and a root `index.html` that links to the main comparisons. Git ignores local DuckDB state and runtime stores. `RESULTS.md` records the run scope, caveats, and attribution for the published memory-bench excerpts.
For the tiny Ollama model in this benchmark, use `--answer-model ollama_native --model-max-tokens 512`; the installed OpenAI-compatible endpoint ignored the requested output limit and timed out. `--run-id` resumes the saved source ledger and bank namespaces after a failure.
